O que é

Um time de agentes, não uma ferramenta isolada

O ITAGMKT (INEMA Time de Agentes de Marketing) roda uma campanha inteira — da pesquisa à publicação — como um pipeline de 5 estágios, cada um com seus próprios agentes especialistas.

🤖 13 agentes especialistas

Research, Diretor Criativo, Copywriter, Ad Designer, Video Quick/Pro e um agente por plataforma (Instagram, YouTube, TikTok, Facebook, Threads, LinkedIn) + Distribution.

💬 Controlado 100% pelo Telegram

O bot (telegram/bot.js) recebe comandos, mostra o painel de config da campanha e pausa pra aprovação em cada etapa — sem precisar abrir terminal.

⚙️ Cada agente é um Claude subprocess

Todo agente roda como claude -p <prompt> --dangerously-skip-permissions, lendo seu próprio SKILL.md. O worker escuta o stdout e avança o pipeline via BullMQ/Redis.

Como funciona

Pipeline de 5 estágios

Cada campanha passa pelas mesmas 5 etapas; cada uma pode ter aprovação humano (padrão, pausa no Telegram), agente (revisor automático) ou auto (segue direto).

1. Brief & Narrativa→ 2. Imagens→ 3. Vídeo (Quick/Pro)→ 4. Plataformas→ 5. Distribuição

1 · Brief & Narrativa

Research Agent pesquisa via Tavily → Diretor Criativo define ângulo → Copywriter escreve a narrativa central. [aprovação]

2 · Imagens

Se a fonte for api, gera imagens (KIE/Pollinations); o Ad Creative Designer monta HTML → PNG via Playwright (carousel + stories). [aprovação]

3 · Vídeo

Quick: slideshow 10-20s, sempre roda. Pro: 30-60s cinematográfico sob demanda (narração → direção de fotografia → scene plan → render). [aprovação]

4 · Plataformas

Um agente por rede (Instagram/YouTube/TikTok/Facebook/Threads/LinkedIn) adapta imagem, vídeo e texto ao formato de cada uma. [aprovação]

5 · Distribuição

Distribution Agent guarda mídia no Supabase Storage, monta o calendário/Publish MD e publica via API quando referenciado pelo nome. [aprovação final]

Pré-requisitos

O que precisa estar no ar

Node.js 18+, Redis (fila BullMQ) e um bot do Telegram. As API keys de mídia (imagem/TTS) são opcionais — o sistema cai pra fallback gratuito quando faltam.

Instalar dependências

Instala o projeto raiz, o sub-projeto Remotion e o Chromium do Playwright (usado pra renderizar os ads em HTML→PNG).

# na raiz do repo
npm install
cd remotion-ad && npm install && cd ..
npx playwright install chromium

Redis (fila de jobs)

O orchestrator enfileira cada stage no BullMQ, que precisa de um Redis rodando.

# via Docker
docker run -d --name redis -p 6379:6379 redis:alpine

Variáveis de ambiente

Copie o template e preencha ao menos Tavily + Supabase (storage de mídia). Provider de imagem/TTS/publicação são opcionais.

# cria o .env local
cp .env.example .env
Guia de uso · passo a passo

Do zero à primeira campanha

Comandos reais do repositório — sem placeholder.

1

Configure o .env mínimo

No mínimo, preencha Tavily (pesquisa) e Supabase (storage de mídia das campanhas). Provedores de imagem, narração e APIs de publicação são recomendados mas opcionais — o sistema cai pra fallback gratuito.

# .env — mínimo pra rodar
TAVILY_API_KEY=
SUPABASE_URL=
SUPABASE_SERVICE_ROLE_KEY=  # bucket "campaign-uploads" marcado como público
2

Suba o bot e o worker (PM2)

O bot recebe os comandos do Telegram; o worker executa os agentes via Claude CLI, um por stage.

npx pm2 start telegram/bot.js --name bot
npx pm2 start pipeline/worker.js --name worker  # sobe os dois processos
npx pm2 logs bot --lines 30       # acompanhar logs
3

Inicie uma campanha pelo Telegram

No chat do bot, dispara o pipeline completo pra um projeto/marca já configurado em prj/<projeto>/.

/campanha minha_campanha  # inicia o pipeline de 5 estágios
/status                   # mostra a fase atual
/modos etapa3 auto        # ajusta o modo de aprovação de uma etapa
4

Ou enfileire via payload, sem Telegram

Pra testes/CI, dá pra rodar o orchestrator direto com um JSON de payload de campanha.

node pipeline/orchestrator.js --file pipeline/payloads/coldbrew_demo.json
5

Publique (dry-run antes)

A publicação real só roda quando você referencia o Publish MD gerado pelo Distribution Agent — antes disso, use --dry-run pra conferir.

node pipeline/publish_now.js prj/inema/outputs/pascoa_2026-04-20 --dry-run  # simula
node pipeline/publish_now.js prj/inema/outputs/pascoa_2026-04-20            # publica de verdade
6

Confira os providers de mídia ativos

O sistema escolhe automaticamente o provider de imagem/voz/música com base nas chaves configuradas no .env.

npm run media:status  # lista o que está ativo (imagem/TTS/música)
